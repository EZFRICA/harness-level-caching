**Reading.**

- cama, which renders the whole active set in a stable order, had 75.0% to 78.5% of its prompt tokens served from the provider cache; topk, which selects blocks per query, had 55.2% to 62.7%, on three replicates each.
- cama also sent more prompt tokens (about 77k against 50k to 54k), so its hot path cost is close to topk's: the higher cached share pays for the larger prompt, it does not make the run cheaper.
- naive is the cheapest arm by a factor of about four because it has no cold path: memory extraction is more than half of cama's and topk's bill, as on Gemini.
- naive also called fewer tools and answered faster; nothing here shows its answers were as good.
- Switching H3 off (one run) left the cost inside the spread of the cama replicates.

**Limits.**

- Three replicates per mode, one for noh3; 24 turns of one synthetic French scenario with simulated tools; latency stats skip the first turn.
- Provider caching is best effort and its cache is shared between customers of a model: each run opens its system prompt with its own salt (its run id), so hits come from the run itself.
- There is no ablation of the stable order itself: with an implicit-only provider CAMA_PREFIX_CACHE=none changes the label, not the request.
- Prices official, read from the provider's model listing; these figures hold for this provider only, not for Gemini or a self-hosted server.
- Answer quality is not measured.
