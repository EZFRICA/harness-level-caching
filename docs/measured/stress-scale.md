**Reading.**

- v1, without admission control: sixteen agents on one worker answered nothing (0 of 192). The worker never crashed; concurrent model inference starved its event loop and it stopped accepting connections.
- v2, with one inference at a time, bounded agent opening and a fast busy answer: sixteen agents get 190 of 192 answers at 3.0 requests per second, thirty two agents 356 of 384 at 4.2.
- The answers still missing come mostly from the first turn: many agents opening at once on one worker queue longer than the client's retries. A cold start limit, not a steady state one.
- A second worker nearly doubles throughput for eighteen agents and halves the tail; the third adds little because eighteen agents cannot send more than about nine requests per second.

**Limits.**

- Echo model with a latency model fitted on real calls; one run per point; all containers on one machine.
- The v1 series stopped at sixteen agents: its next runs would have been built from changed code.
