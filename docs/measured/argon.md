# Gemini 4 Argon, implicit cache only, with a memory above its 4096 token minimum

Generated by `harness-cache figures` from `docs/measured/runs/`. Do not edit.

**Question.** On the owner's production model, where only implicit caching exists, what do naive, extract and extract with decision 0013 cost over the 32 turn recall scenario when the memory is large enough to be cached?

| `argon-onnx-memlarge-naive-v1` | naive | 13/13 | 5986 [3788, 9614] | 64169 | 0.0% | 0.1452 | 0.0000 |

Reproduce: `docker compose exec -T -e HC_LLM=gemini -e HC_MODEL=gemini-4-argon -e HC_EMBEDDER=onnx -e HC_MAX_USD=1.0 -e HC_MAX_MEMORY_TOKENS=8000 -e HC_CAPACITY=24 [-e HC_EXTRACT_REPLACE=on -e HC_EXTRACT_EVERY=2 -e HC_MEMORY_REFRESH=epoch -e HC_PAGE_IN_TAIL=on -e HC_WINDOW_EPOCH=10] hc harness-cache run /scenarios/memory_large_fr_v1.jsonl --fresh --mode <naive|extract> --run-id <run id>`

**Reading.**

- naive was the cheapest (0.145 USD) with full recall: it carries no memory, so its prompt stayed under the 4096 token minimum and nothing was cached, but there was little to send.
- extract sent its 4400 token memory on every call and only 17.5% of its prompt tokens were cached; it cost 0.54 USD. The caching page states that Gemini 4 caches the previous request only when the new one adds at least 2050 tokens, which most of these calls do not.
- Decision 0013 raised the cached share to 56% and cut extract's cost by 41% (0.32 USD), but recalled 11 of 13: the door code was never written to memory, because the extraction call covering that turn proposed no operation.

**Limits.**

- One run per arm on one scenario; the large memory is six synthetic note blocks added to the seed.
- Prices official, read 2026-10-24, valid until 2026-11-30; they double from 2026-12-01.
- Whether the missed fact comes from extracting every two turns or from chance cannot be told from one run.
