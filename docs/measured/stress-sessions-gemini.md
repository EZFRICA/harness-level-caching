**Question.** Over 200 turns with recurring topics, what do the three policies cost and how fast do they answer, with real extraction and real provider caches?

Latency statistics skip the first turn of each run. Reproduce: `CAMA_LLM=gemini CAMA_EMBEDDER=onnx docker compose up -d && docker compose exec -T cama cama run /scenarios/generated/zipf_200_s20261023.jsonl --fresh --mode <mode>`

**Reading.**

- cama cost 37% less than naive and answered faster, with the 95% intervals of the median turn apart.
- cama created no provider cache: its stable part stayed just under the explicit minimum of 1024 tokens (163 creations skipped for that reason). Its saving came from the bounded prompt alone.
- naive's prompt grew to about 11500 tokens and Gemini's implicit cache served 57% of its tokens, starting at turn 64 with a 3635 token prompt: implicit caching exists below the 5000 seen in the first probe.
- topk was the cheapest: per query selection keeps the prompt smallest when no cache can be used.
- Real extraction wrote memory 38 times in 200 turns (3 created, 35 updated) where the echo extractor wrote every turn.

**Limits.**

- One run per mode, generated English scenario, simulated tools; answer quality is not measured.
- The explicit cache could not engage at this memory size: a larger stable prefix is the next experiment.
