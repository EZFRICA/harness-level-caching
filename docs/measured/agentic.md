Latency statistics skip the first turn of each run. Reproduce: `CAMA_LLM=gemini CAMA_EMBEDDER=onnx docker compose up -d && docker compose exec -T [-e CAMA_PREFIX_CACHE=none | -e CAMA_TOOL_CACHE=off] cama cama run /scenarios/agentic_fr_v1.jsonl --fresh --mode <cama|topk|naive>`

**Reading.**

- The explicit prefix cache cuts the hot path cost by about 60% against its ablation (nopc), and every agentic step reuses it.
- It also makes turns slower: the cama replicates sit around 2.4 to 2.7 s against 1.8 s without the cache, with confidence intervals apart. Explicit cached requests are slower on this provider.
- The cold path dominates CAMA's bill: memory extraction costs more than the prefix cache saves, so naive, which has no cold path, is the cheapest arm over 24 turns.
- The tool cache served 7 of 23 tool calls and removed about 200 ms of tool time per turn at the median; its effect on turn latency is inside the model's variance.
- cama v2 and v3 were launched as ablations but the flag never reached the container; their manifests say so and they are kept as replicates.

**Limits.**

- 24 turns, one synthetic French scenario, simulated tools; latency stats skip the first turn.
- Prices: official for input, output, cache read and storage; cache creation priced as input is an assumption.
- Answer quality is not measured, so a cheaper arm is not shown to be as good.
